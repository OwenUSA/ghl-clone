## Fixed in this pass (found by the audit, not by eye)

**Contacts** — was missing 7 pieces of chrome and 2 columns:

- `Import` (disabled, out of scope) and `Add Contact` (real — creates a contact,
  fires the new-lead automation)
- smart-list row: `All` tab + `+ Add Smart List` (GHL renders the `+` as its own element)
- `Filters`, `Sort` (5 sort fields + direction, wired to the API), `Manage fields`
  (toggles columns for real)
- **`Tags` column** and **`Last activity (EDT)` column** — both were absent entirely.
  Backend now returns tags per row and computes last activity from the newest event on
  the contact's conversation.
- select-all checkbox in the header

Bug found while doing it: `ContactOut.model_validate(row, from_attributes=True)` read the
ORM `tags` relationship (`ContactTag` rows) into a `list[str]` and raised — but **only for
contacts that actually had a tag**, so the first test request looked fine. Rows are now
built explicitly.

## Remaining known gaps

Listed rather than silently skipped.

### Conversations
- `Select all` checkbox in the inbox list
- `View contact details` — we render a `↗` icon, GHL uses a text link
- `General Info` / `Additional Info` collapsible sections in the contact panel
- `Audit logs`
- unread `New` divider in the thread
- audio playback-speed control (`1x`)

### Opportunities
- `Add opportunity` and `Import` buttons
- `Advanced filters (1)` — we ship a simpler Status select instead
- `Sort` menu
- saved-view tab row (`Open opportunities` / `+ List`)
- GHL splits `Value:` and the stage count/total into separate elements; ours combines them

### Calendars
- `All day` row above the hour grid
- `Meetings` filter dropdown
- user/calendar search box (`Search users, calendars, or groups`)
- ours says `Clear`, GHL says `Clear all`

### Cross-cutting
- Contacts sub-tabs (`Bulk Actions`, `Custom Fields`, `Tasks`, `Companies`) render as
  labels only — no targets behind them
- font sizes present in GHL but not ours: `10px`, `13.6px`, `17px`, `20px`, `22px`
  (mostly notification chrome and the avatar rail we do not reproduce)
- `font-weight: 900` appears in GHL only

## What is NOT comparable

- **Element counts** — different databases, never compared.
- **Record data** — contact names, phone numbers, tag values (`ahs`, `paid`, `sarasota`,
  `workiz-import`), opportunity titles, money amounts. The audit filters these out; the
  remaining "missing" entries in its raw output are overwhelmingly of this kind.
- **Counts in labels** — GHL shows `268 Contacts`, ours `269` (a contact was created
  while testing the Add Contact flow).
